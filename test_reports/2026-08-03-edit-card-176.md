# Test Report — editing a saved card

**PR:** [kuantorflow#190](https://github.com/Kuantor/kuantorflow/pull/190) + [kuantorflow_automation#44](https://github.com/Kuantor/kuantorflow_automation/pull/44) · **Issues:** [kuantorflow#176](https://github.com/Kuantor/kuantorflow/issues/176), [#186](https://github.com/Kuantor/kuantorflow/issues/186) · **Date:** 2026-08-03

## Summary

Every content field of a saved card is now editable, under the same ownership
rule as deleting, with the rename running #101's duplicate check against
itself excluded. #186 rode along because it is the same code. **498 offline
tests pass** (was 464) plus 4 new `db`-marked ones. `applog.card_edited()`
finally has a call site, three weeks after it was written for this.

## What changed

- **`utils.update_flashcard()`** — ownership inside the `UPDATE`, the
  duplicate check excluding the card itself, and **only the keys present in
  the entry** are touched, so a field the editor never rendered is left alone.
- **`utils.find_duplicate()`** — returns the blocking card *and its owner*, so
  the app can say whether it is even visible to this visitor (#186).
- **`POST /flashcards/<topic>/edit/<id>`** — JSON, so a refusal lands in the
  dialog without losing what was typed. Refuses anonymous, blocked, and
  not-yours; 409 on a rename collision; 404 on a missing card.
- **The pencil and dialog** in `flashcards.html`, greyed by the same rule and
  with the same `aria-disabled` treatment as #162's cross.
- **`applog.card_edited()` / `card_edit_denied()`** now called.
- **#186** — `duplicate_notice()` adds one sentence when the blocking card is
  hidden by #127's filter, on both the review popup and the automatic-add path.

## Automated tests

- **Added:** `tests/test_card_editing.py` — 34 offline tests across the
  storage layer, the duplicate rule, ownership, the route, the log and the
  pencil, plus the four #186 cases.
- **Added:** `tests/test_card_editing_db.py` — 4 `db`-marked tests for what a
  fake cannot prove: `created_at` surviving an edit, examples round-tripping
  as lists, and the duplicate rule against the real NULL-safe comparison.
- **Suite result:** `pytest -m "not live"` — **498 passed, 10 skipped**
  (was 464 passed, 6 skipped). `RUN_DB_ROUNDTRIP=1 pytest -m db` — **10 passed**.

## A regression the existing suite caught

The first implementation carried every field in `data-` attributes on the
pencil, which **leaked hidden-language translations into the page** — exactly
what #46/#79/#111 forbid. Three language-visibility tests failed on the first
run.

The fix changed the design for the better: `update_flashcard()` now treats a
**missing** key as "leave this alone", distinct from a key holding `None`
("clear it"). The dialog renders no field for a hidden language, so it is
never submitted, and the card keeps it.

## Manual & browser verification

A local harness was used to sign in without a Google round trip — the app's
session cookie is HttpOnly, so the browser cannot be handed one. It sets that
one flag and adds a login route, lives in a scratch file, and touches nothing
in the repository. A probe account with one owned card and one unowned card
was created on a throwaway topic and removed afterwards.

- **The pencil**: active on the owned card, greyed on the other with
  *"This card was created by admin or another user. You cannot edit the card."*
- **The dialog** opened pre-filled with all eight fields; examples shown one
  per line.
- **A real edit** (word, explanation, examples) →
  `resilient` → `resilient-edited`, explanation replaced, examples stored as a
  two-item array. **`translation_ukr` untouched. `created_at` unmoved** (same
  second as its unedited sibling). Log:
  `EDIT word=resilient-edited pos=adjective id=100
  changed=word,explanation_en,examples_en source='card page'`.
- **A colliding rename** → dialog stayed open, typed value kept, Save
  re-enabled, message *"Another card for 'somebodyelse' (noun) already exists,
  so this one cannot be renamed to it."* Database unchanged.
- **A hand-made POST** for the card the visitor does not own → **403**, the
  not-yours message, an `EDIT-DENIED … reason='not owner'` line, no change.
- **#186** — with the filter on, adding a word whose only card is hidden
  returned `note: "It is in the shared deck, hidden from you by your 'Use only
  individual cards' setting."`
- **Cleanup**: probe cards, probe user, `settings/config-14.json` and both
  temporary launch configs removed; the database afterwards holds only the
  real account.

## Result

**Pass**, against every acceptance criterion in #176, and #186's recommended
option (better message, no change to what is stored).

Worth noting:

- **The dialog was driven from the page's own script** rather than by clicking
  each field, after element references went stale mid-interaction twice. The
  clicks it performs are the page's real handlers, and the results were
  verified in the database and the log rather than on screen.
- **`created_at` was checked against real MySQL**, not asserted from a fake:
  the risk was MySQL's implicit `ON UPDATE CURRENT_TIMESTAMP` on a first
  timestamp column, which no stub would ever reproduce.
- **Editing a card's topic is out of scope** and remains #177.
