# Test Report — Action logs (cards, dictionaries, parsed files)

**PR:** kuantorflow#155 (+ kuantorflow_automation#25) · **Issue:** kuantorflow#30 · **Date:** 2026-07-27

## Summary

A new `applog.py` writes a plain-text action trail into `logs/`: `cards.log`,
`dict.log` and `parsed_files.log`, rotating every 30 days. Every logged action
was driven against the running app and the resulting lines inspected; 19 new
offline tests cover the wiring. Suite: **150 passed**, was 131.

## What changed

- **`applog.py` (new)** — three rotating loggers behind small named helpers
  (`card_created`, `card_skipped`, `card_edited`, `card_deleted`,
  `card_delete_missed`, `lookup_started`, `translations_fetched`,
  `definitions_fetched`, `lookup_finished`, `lookup_failed`, `file_parsed`,
  `file_rejected`, `terms_split`) plus a `Timer` for the `ms=` fields.
  - Line format `<timestamp> ACTION key=value …`; values containing spaces are
    quoted, so `grep "word=brittle" logs/*.log` works.
  - `TimedRotatingFileHandler(when="midnight", interval=30, backupCount=12)` —
    Python has no calendar-month unit, so a month is 30 days; a year of
    rotations is kept.
  - **Every helper swallows its own errors** — a full or read-only disk costs a
    log line, never a saved card.
  - `KF_LOGS_DIR` redirects the directory; resolution is lazy, so the test
    suite can point it at a temp dir per test.
- **`app.py`** — `_save_and_log()` is the one place cards are saved and logged;
  all three save paths (review popup, automatic add, Mykola chat) go through
  it, each with its own `source=`. Deletes (hit and miss) log from the delete
  route. Uploads log `PARSE` / `REJECT` with the file, its size and the card
  count. The lookup route logs the `LOOKUP` line, which carries the identity
  the parser cannot see.
- **`parsers.py`** — `lookup_word()` logs each provider it actually called
  (`TRANSLATE` / `DEFINE`), with elapsed ms, error, and `fallback_from=` when a
  silent fallback kicked in; `_provider_name()` names the site from the backend
  function, so an unknown setting is logged as the provider that really ran.
  `_split_glued_translations()` logs the AI split, which fails silently by
  design.
- **`.gitignore`** — `logs/*` with `!logs/.gitkeep` (the global `*.log` rule
  does not cover dated rotations like `cards.log.2026-08-26`).
- **README / CLAUDE.md** — the log files, the line format, rotation, and the
  convention that a new save/delete path must log.

## Automated tests

- **Added:** `tests/test_action_logs.py` — 19 tests: each card action and its
  `source`, anonymous vs signed-in attribution, duplicate → `SKIP`, delete hit
  and miss, the dict lines for a normal lookup and for a Bing→Google +
  Oxford→Reverso fallback, a failed lookup, upload `PARSE`/`REJECT`, the AI
  split, the three file names, the rotation settings (`when`, 30-day interval,
  12 backups), value quoting, `propagate is False`, and that a logger raising
  `OSError` still leaves the card saved and the response 200.
- **Updated:** `conftest.py` — autouse `action_logs` fixture redirecting
  `applog.LOGS_DIR` to `tmp_path`, so no test writes into a real checkout.
- **Suite result:** `pytest -m "not live"` — **150 passed**, 1 skipped,
  6 deselected (was 131). Run twice, with and without test-order
  randomisation.

## Manual & browser verification

Dev server against local MySQL, driving every logged action in one pass, then
reading the three files:

| Action | Line written |
|---|---|
| Look up `brittle` (real providers) | `LOOKUP … translator=google dictionary=oxford user=anonymous`, `TRANSLATE … provider=google lang=uk pos_count=1 ms=107`, same for `ru`, `DEFINE … provider=oxford pos_count=1 ms=1346`, `RESULT … cards=2 ms=1582` |
| Add a reviewed card | `CREATE word=brittle pos=adjective topic=probe30 id=68 langs=ukr source='review popup' user=anonymous` |
| Add the same card again | `SKIP … reason=duplicate` |
| Upload `LucidDream.txt` | `PARSE file=LucidDream.txt bytes=403 cards=1 topic=probe30 ms=0 user=anonymous` |
| Upload `scan.pdf` | `REJECT file=scan.pdf error='Unsupported notes format: .pdf'` |
| Delete the card | `DELETE id=68 word=brittle topic=probe30 source='topic page'` |
| Delete a missing id | `DELETE-MISS id=999999` |

Test rows were removed from the local DB (back to 47) and the probe log files
deleted; `git check-ignore` confirms both `logs/cards.log` and
`logs/cards.log.2026-08-26` are ignored while `logs/.gitkeep` is tracked.

## Result

**Pass**, with one gap called out rather than invented: the app has **no
edit-a-saved-card feature**, so the issue's "editing a card" has nothing to
hook into. `applog.card_edited()` is implemented and tested so that an edit
feature logs from its first commit — the only item of the issue not wired to a
live call site.
