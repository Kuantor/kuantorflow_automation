## 3. What it is now

Six modules, and the dependency runs **one way**:

```
web.py  <-  icons.py  <-  cards.py  <-  rounds.py  <-  chat.py  <-  app.py
```

| module | lines | KB | defs | routes | proc. | holds |
|---|---|---|---|---|---|---|
| `web.py` | 728 | 33 | 28 | 0 | 0 | the Flask object, configuration, identity and permissions, the two spending guards, the SSE frame |
| `icons.py` | 119 | 5 | 5 | 0 | 0 | topic and activity icons, as Jinja filters |
| `cards.py` | 1,364 | 65 | 27 | 16 | 0 | the deck, every card read and write, `_save_and_log()`, #406's topic builder |
| `rounds.py` | 1,550 | 73 | 41 | 5 | 1 | the games chassis, ten rounds, the quiz |
| `chat.py` | 960 | 41 | 44 | 9 | 2 | Mykola: the agent import, the singleton, the chat routes, the chat logs |
| `app.py` | **538** | 21 | 17 | 8 | 5 | the keyword gate, Google sign-in, settings, account deletion, four side-effect imports |

**Nothing may import `app.py`.** That is the property the whole split rests on:
the moment a feature module imports it, the route table comes along behind it
and the separation is undone. It is asserted, per module, in
`tests/test_web_is_the_shared_module.py`.

`app.py` imports `cards`, `chat`, `icons` and `rounds` **for their side
effects** — routes, context processors, Jinja filters and `GAME_ROUNDS` all
register themselves — and asks them for nothing except `cards._save_and_log()`
and `cards.DEFAULT_TOPIC`, which it reaches through the module.

### The admission rule for web.py

**`web.py` takes only what two or more feature modules need.** Without a
stated rule it becomes `app.py` under another name, and that is the one way
this refactor could fail while every test stayed green.

It decided the two borderline cases:

- the **spending guards moved there**, because `_generation_refusal()` is
  asked by #237's reader *and* #406's topic builder — two different features;
- **`GENERATED_TEXT_KEY` stayed with the round**, because only the reader
  reads it.

`icons.py` exists for the same reason in reverse: the topic tiles belong to
`cards.py` and the activity tiles to `rounds.py`, so the icons could live in
neither — and giving them 119 lines of their own kept `web.py` from absorbing
them.

## 4. The decision that governed everything: route modules, not blueprints

Blueprints are the idiomatic Flask answer and they **rename every endpoint**.
`url_for('index')` becomes `url_for('cards.index')`. The templates use **32
distinct endpoints across roughly 90 call sites**, and a missed one is a 500 at
render time — not a failed import, not a red test.

Issue #250 is a live reminder that endpoint identity is load-bearing here:
`/quiz` and `/quiz/<topic>` are deliberately two endpoints, because `url_for`
otherwise picks the path converter and the multi-topic URL becomes
unbuildable.

So: **route modules registered against the one `app` object**, keeping every
endpoint name. Less idiomatic, and it needs an answer for the import cycle —
which is what `web.py` is.

**The result of that decision: zero template edits across nine PRs.**

## 5. The prerequisites — two PRs that moved no application code

### 5.1 Prove the suite stays offline (automation#153)

`conftest.py` held the promise that no test touches a real database, and it
kept that promise by stubbing names **on the `app` module**. That worked only
while every database call lived in `app.py`.

Simulating a single moved helper flagged **21 routes**, every one answering 200
while reading a real database, with the suite green. This project had already
paid that bill once: tests incrementing the live `text_generation_usage`
counter until an account hit its daily ceiling and unrelated tests began
failing for reasons nobody could see.

`tests/test_suite_stays_offline.py` patches `utils.get_db_connection` to raise
and walks every route derived from the app's own URL map. **The attempt is the
assertion, not the status code** — several read paths catch a dead database and
degrade to an empty page on purpose, so a route that reached a real connection
can still answer 200. Asserting on the response was this test's first version,
and it passed while the very move it exists to catch was simulated against it.

### 5.2 The patch-target migration (#436, two PRs)

`from utils import get_topics` **copies** the function into the importer's
namespace. There are then two names for one function, and the suite stubbed the
copy. Move a caller to a new module and the stub stops reaching it — silently.

Measured cost before starting: **343 `monkeypatch.setattr(app_module, ...)`
calls across 118 test files, 54 distinct names.**

The change: `import utils` and `utils.get_topics(...)`, resolved at call time,
so one `monkeypatch.setattr("utils.get_topics", fake)` reaches every caller in
every module — including ones not yet written.

- **59** call sites rewritten in `app.py`
- **43** test files plus `conftest.py` repointed
- offline and database tiers unchanged; `--collect-only` identical to `main`

This is the step that made every later move cheap. It was filed as its own
ticket rather than discovered inside a move, because a mistake in `conftest.py`
breaks all 2,073 tests at once.

### Step 3 — web.py (#435)

The Flask object, the secret, the session lifetime, the environment readers,

*user* of those names stayed in `app.py`.

### Step 4 — identity and permissions (#438)

Thirty names, 317 lines: who is asking, whether they are blocked, an admin or

### Step 7 — card routes and icons (#441)

1,298 lines into `cards.py`, 94 into `icons.py`, and 8 lines of SSE framing into

882 lines: the agent import, the `_mykola_agent` singleton, the chat routes,

Measured **self-contained in both directions** before it moved — which is

### Follow-up — scripts/ (#444, ticket #442)

Six console one-offs out of the root: `apply_schema.py`, `seed_topics.py` +

They can move where the app's modules cannot, and that difference is the whole

All five were **executed** from the new location against the real local MySQL,
not merely imported.

## 7. What went wrong

Four failures, three of them silent. None reached `main`.

### 7.1 A decorator left behind, rerouting a live endpoint

A decorated function's `ast` line number is the `def`, **not the decorator**. A
block boundary drawn from it leaves `@app.route` behind — and the orphan then
attaches to the *next* function.

It happened twice:

- **step 7**: `topics_json`'s decorator was left behind and produced a
  `SyntaxError` — loud, and lucky.
- **step 8**: two decorators were orphaned and both reattached silently.
  **`/mykola/chat` was answering with `test_db_connection`**, and
  `inject_mykola`'s context processor had landed on a `before_request`. Neither
  was a syntax error. The suite could not see either.

Caught by counting every route, context processor and `before_request` across
all six modules and comparing with `main`: **46 before, 46 after.** That check
is now the documented procedure in `CLAUDE.md`.

### 7.2 The database tier went silent

Moving `apply_schema.py` into `scripts/` **disabled all 127 database tests**.
Each `*_db.py` gates itself on `_prerequisites_met()`, which checks the
environment *and* `SCRIPT.exists()` — so to pytest, "the file moved" and "the
tier is switched off" are the same thing.

Nothing was red. The only signal was the run finishing in **60 seconds instead
of four minutes**, noticed by eye.

| | passed | skipped | time |
|---|---|---|---|
| broken | 2,109 | 143 | 1:02 |
| fixed | 2,250 | 3 | 3:51 |

A missing script is a broken checkout, not an environment prerequisite, so it
is now an assertion rather than a skip — derived from the `*_db.py` files, so
it covers a path added tomorrow.

### 7.3 A module prefix shadowing a local variable

`topics_json` already had a local variable named `icons`. A blanket
`topic_icon(` to `icons.topic_icon(` rewrite shadowed the module with the local
and `/topics.json` began answering **500**. Three tests caught it within one
run.

A scan of all six modules for locals shadowing an imported module name then
found a second: `_cards_for_chat` had a local named `cards` — harmless that
day, and a trap the moment that function moved to `chat.py` the following step.
Renamed before it could bite.

### 7.4 A branch cut from a stale origin/main

In step 8 the test branch was created without fetching first, so it lacked step
7's already-merged test sweep. Time was spent re-deriving work that existed.
No harm to the result; the lesson is to fetch before branching, and that a code
PR merging does not mean its paired test PR did.

## 8. Tests this produced

Three files that did not exist before, all guarding failures the rest of the
suite **cannot see**:

| file | guards |
|---|---|
| `test_suite_stays_offline.py` | no route opens a real database connection |
| `test_web_is_the_shared_module.py` | no shared module imports `app`; `app.py` reaches names through the module; feature modules imported for side effects only |
| `test_scripts_run_from_their_directory.py` | each script runs from the repo root; the database tier's paths resolve |

Every assertion in them was **proved to fail first**, per the repo's standing
convention. Two examples of why that matters:

- **`test_web_is_the_shared_module.py`**: a bare `import app` in `web.py` leaves
  **all 2,082 other tests green** while the ticket's entire purpose is gone. So
  does a bare `is_admin()` in `app.py`. That file is the only thing that notices
  either.
- **`test_scripts_run_from_their_directory.py`**: deleting one
  `import _bootstrap` leaves **2,095 tests passing**, because `conftest.py` puts
  both directories on `sys.path` — the script would only fail on the
  deployment, at the moment somebody is following the deploy instructions.

### Three existing tests were found to be vacuous or misdirected

- **`test_the_vet_does_not_vouch_for_words_in_confirmed_words`** could not fail,
  for two independent reasons: it stubbed `remember_confirmed_word` with a bare
  assignment on a module nothing had read since #436, *and* it never seeded
  `random`, so no word was ever rejected and there was nothing to vouch for in
  the first place. Both fixed; verified by making the vet actually vouch.
- **`test_the_note_is_written_once`** checked a claim about the whole codebase
  by grepping one file. After the move that count was zero — one rename from
  passing for the wrong reason. It now counts across every module.
- **`test_the_app_loads_its_own_env_before_the_agents`** (#412) compared two
  string offsets inside `app.py`; with the agent import in `chat.py` there was
  nothing left to compare. It now asks a subprocess for `sys.modules` order.
  Worth stating plainly: **that invariant is now harder to break than it was** —
  two independent changes are needed, and each alone was verified to leave the
  test correctly passing.

## 9. Rules this produced, now written into CLAUDE.md

1. **Reach a module through its name** — `web.is_admin()`, never a copy bound
   at import. A bare call still answers correctly; it is simply the one site a
   stub can no longer reach.
2. **`app.py` imports feature modules for side effects only.** A
   `from rounds import ...` means something was left half-moved.
3. **`web.py` takes only what two or more feature modules need.**
4. **Moving a block? Compare the routes** — before and after, across every
   module.
5. **`scripts/` holds what is run, not imported**, and each script opens with
   `import _bootstrap`, whose position is load-bearing.

## 10. Verification

Every step was verified the same way.

- **An AST pass** listing names each module uses but does not define. This is
  what found `oauth` (lowercase, missed by a regex) and `_current_email` in the
  first, reverted attempt — each of which had cost a full suite run to
  discover.
- **Both test tiers**, compared against `main` run on the same machine, so the
  numbers meant something.
- **A real-MySQL smoke walk** at every step — the part offline stubs cannot
  prove. By the last steps this was all 29 fillable GET routes, a ten-answer
  graded POST, `/topics.json`'s four keys, all nine games for both picker and
  round, both quiz endpoints, the worksheet, and Mykola: agent available,
  `docs/user-guide.md` found, widget rendered, chat pages answering.

Final: **2,109 offline, 2,250 with a real database, 3 skipped.**
